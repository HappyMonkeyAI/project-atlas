# Project Atlas design

## Design direction

Combine the strongest parts of the references:

- Collapsible icon-first navigation from the constellation direction.
- Clear right inspector with evidence and unlocks.
- Multiple map views sharing one visual language.
- Dark graphite base with restrained cyan, amber, green, blue, and purple states.
- “Game tech tree” metaphor used for relationships, not decoration.

## Interaction principles

- Explore spatially, understand causally, then act.
- Every selected node should answer: What is it? Why is it here? How ready is it? What does it unlock?
- A recommendation is incomplete without evidence and an explicit next step.
- Dense graph views should be paired with a calm inspector and clear filters.
- Collapse navigation to give the map room; never hide the inspector during core exploration.

## View roles

- Constellation: “What belongs together?”
- Radial: “Where is my attention and capability concentrated?”
- Tree: “What must happen before this idea?”
- Hex: “What focused capability should I research or build next?”

Keep Constellation as the landing view for portfolio orientation; use Tree as the explicit causal/planning mode. Do not promote Tree to the default until a live planning-session comparison shows that it improves orientation without hiding useful context.

## Accessibility and usability

- Status should never rely on color alone.
- Nodes need readable labels and keyboard focus.
- The inspector must remain usable at narrow widths.
- Provide list/table fallbacks for large or dense graphs.
- Avoid exposing private note content in screenshots or exports.
